# MIRON — твой напарник для тренировок

Работающая локальная первая версия на Next.js / React / TypeScript. Макс и Лика, онбординг, кабинет, тренировочные карточки, подходы, опыт, достижения и чат. Лендинга в этой итерации нет. Название папки `LightWeightBaby` сохранено для существующих путей.

Репозиторий проекта: [JakuninOleg/Miron](https://github.com/JakuninOleg/Miron).

## Открыть сейчас

- **Основной вход через Яндекс:** http://localhost:3000/sign-in. VK пока неактивен, почтовый вход отложен.
- **Новый дизайн-прототип:** http://localhost:3000/demo → comic-знакомство и новый дашборд.
- **Регрессионное офлайн-демо:** после запуска собранной PWA по инструкции ниже — http://localhost:3040/demo?legacy=1.
- **Письма при включённом email/password:** http://localhost:8025. Mailpit принимает письма локально; внешняя доставка не подключена.

После первого входа открывается готовое знакомство, затем новый дашборд с фактическими данными аккаунта и входом в конструктор. Завершение сохраняется в БД: при следующих входах знакомство не повторяется. Разработка позволяет повторить историю из профиля без сброса аккаунта; в production эта кнопка отключена.

В явном legacy-demo выбери напарника и условия, начни занятие и нажми «Для офлайна» в программе. Дождись подтверждения загрузки. Затем можно отключить сеть, записывать подходы и перезагружать сохранённые экраны. Демо хранится только на устройстве и обозначено в интерфейсе. Очистка данных браузера удаляет его.

Офлайн проверяется на **собранном приложении**. `next dev` использует горячую перезагрузку и не подходит для проверки офлайн-старта. Запуск на `3040` по HTTP предназначен для локального демо: production-авторизация требует HTTPS. Для телефона нужен отдельный HTTPS-стенд; `localhost` телефона не является адресом этого компьютера.

## Повторить локальный запуск

Нужен Node.js 22+; текущая проверка выполнена на Node.js 24 и Windows. Из корня проекта:

```powershell
npm ci
npm run db:local
npm run db:migrate
npm run db:seed
# Mailpit нужен только при AUTH_EMAIL_PASSWORD_ENABLED=true
npm run mail:local
npm run dev
```

`db:local` создаёт отдельный PostgreSQL 18.4 в `.local/postgres`, слушающий только `127.0.0.1:55432`. Системная служба не устанавливается. Случайные локальные пароли и auth secret сохраняются в игнорируемом `.env.local`; существующие значения не заменяются. `.env.example` содержит только шаблон. Локальная роль БД пока административная; для размещения нужны отдельные роли миграций и приложения.

Mailpit уже установлен в `.local/mailpit/mailpit.exe`. Для чистой машины установи Windows-сборку из [официальных релизов Mailpit](https://github.com/axllent/mailpit/releases) туда же. `mail:local` запускает скрытый фоновый процесс на SMTP `1025`, интерфейс на `8025`.

Голосовой ввод подключён к Groq с резервным Whisper на сервере: `npm run voice:setup`, затем `npm run voice:start` в отдельном терминале. Расшифровка попадает в редактируемый черновик; офлайн микрофон отключён. [Настройки и проверки](docs/voice-input.md). Для локального `/story/home` нужен `ENABLE_VOICE_PREVIEW=true`; production требует проверенный аккаунт.

Чтобы проверить собранную PWA, в другом терминале:

```powershell
npm run build
npm run start -- --port 3040
```

После изменения кода пересобери и перезапусти этот процесс. `npm run db:stop` останавливает только локальный кластер проекта и сохраняет данные.

## Что реализовано

- Яндекс ID через Better Auth: PKCE, server callback, профиль и единственный trial при регистрации. Живой локальный вход проверен в Brave 11 октября. VK подготовлен в коде, но неактивен и не проверен живым входом.
- Email/password сохранён за `AUTH_EMAIL_PASSWORD_ENABLED`: подтверждение почты, восстановление, одноразовый сброс, отзыв старых сессий. Сейчас флаг `false`: формы и соответствующие server endpoints отключены. SMS не используется.
- PostgreSQL + Drizzle: миграции, профиль и явный инвентарь, каталог с версиями/медиа, планы, занятия, подходы, команды, XP и проба.
- Legacy AI-проба локального прототипа **168 часов / 100 ответов** на аккаунт; конкурентное резервирование и повторы проверены. Это прежний dev-контракт, не условия новой подписки. Целевая модель — [ADR-0004](docs/adr/0004-product-subscription-and-archive-access.md): 7 дней полного MIRON, 299 ₽/месяц, затем read-only архив; product gates ещё не внедрены. Qwen не подключён, списаний нет.
- Comic-знакомство подключено к аккаунту: выбор Макса/Лики и интересов, явное подтверждение совершеннолетия, безопасный повтор после потерянного ответа. Тема и напарник независимы после начального выбора. Смену напарника при `ready`/`active` запрещают UI и сервер.
- Новый дашборд показывает фактические имя, trial, XP, историю и текущую тренировку; входы в программу, разовое занятие и ручной конструктор работают с настоящим аккаунтом. Календарь и свободный AI-диалог ещё не подключены.
- Работа с занятиями: запись подходов, переходы, завершение, история, три достижения. Основное занятие — **50/25 XP**, поддерживающее — **20/10** за полное/частичное; серверный предел **50 XP в день** с доплатой разницы. Пустое прерывание не даёт XP.
- PWA: manifest, favicon, maskable/Apple-иконки, собственные персонажи и логотип, публичная офлайн-оболочка, личные снимки и журнал команд в IndexedDB. Серверный API проверяет владельца, revision и `operationId`.
- Голосовой ввод через запись аудио → Groq → резервный серверный Whisper, с редактированием расшифровки перед отправкой. Без сети микрофон отключён.
- Чат и характеры напарников. В демо работают заранее подготовленные ответы и несколько команд; настоящее AI API пока возвращает понятную ошибку подключения.

В базе **300 редакционных draft-карточек вариантов**: 220 силовых с калистеникой, 30 йоги, 30 стретчинга и 20 мобильности; четыре локальных демонстрационных шаблона. У карточек короткие имена, поисковые алиасы, основной акцент и другие мышцы, места и направления. Дом, зал, улица и воркаут-площадка выбираются отдельно от инвентаря. Проверенные опубликованные программы и картинки техники Макса/Лики ещё не добавлены; настоящий новый аккаунт видит честное пустое состояние программы. Демо не выдаётся за персональную рекомендацию.

## Структура и проверки

`src/app` — маршруты и API; `src/components` — экраны и интерфейс; `src/client` — состояние устройства, голос и офлайн-журнал; `src/server` — auth, доменная логика, БД и будущий AI gateway; `src/shared` — DTO и демонстрационные данные. Правила разработки — `AGENTS.md` и `.cursor/rules/miron.mdc`.

```powershell
npm run typecheck
npm run lint
npm run format:check
npm test
$env:RUN_DB_TESTS = 'true'
$env:MIRON_AUTH_INTEGRATION_TESTS = '1'
node --env-file=.env.local node_modules/vitest/vitest.mjs run
$env:E2E_BASE_URL = 'http://localhost:3040'
npm run test:e2e
$env:MIRON_LIVE_AUTH_E2E = '1'
npx playwright test tests/e2e/auth-live.spec.ts
```

Интеграционные тесты допускают только локальную тестовую БД/почту и удаляют созданные ими аккаунты. Сервер БД и Mailpit должны работать. [Результаты и границы проверок](docs/verification.md).

## Следующие рабочие этапы

Порядок принят для плана в [ADR-0001](docs/adr/0001-training-invariants-and-companion-context.md); внедрение новых этапов ещё не начато.

1. Этап 0.5: единицы результатов, пропуск/частичное завершение, версии программы и условий, сохранение свойств инвентаря и совместимость старых офлайн-команд/ACK.
2. Персонажи: companions, автор каждого ответа и временная передача разговора с сохранением истории.
3. Небольшая опубликованная неделя с авторскими карточками и медиа; product entitlement и bounded offline admission по ADR-0004, затем серверные разговоры/Qwen, инструменты, ограниченный контекст, usage/spend и evals. Legacy `100 ответов` не являются новой нормой; полный trial и paid pipeline измеряются до утверждения ограничений и экономики.
4. Несколько целей, check-in и управляемая память; затем карта участвовавших мышечных групп и навыки с критериями.
5. Живые Яндекс/VK round trip, внешний SMTP и HTTPS-стенд для личного теста на телефоне.
6. Подписка в рублях, push/outbox/worker и инфраструктура в РФ: роли БД, резервное копирование/восстановление, наблюдаемость и нагрузочные проверки. Сейчас нет измерения нескольких тысяч одновременных пользователей.

Подробности: [БД и миграции](docs/database-setup.md), [авторизация](docs/auth-setup.md), [визуальная система](docs/design-system.md), [характеры](docs/companion-personalities.md), [roadmap](docs/miron-roadmap.md). Концептуальные `architecture.md` и `database-model.md` описывают также будущие этапы; физическая схема находится в `src/server/db/schema.ts`.

[Интерактивная ERD, таблица упражнений и графы навыков](docs/reference/README.md): фактический снимок PostgreSQL, общий SVG/PNG, поиск по 300 карточкам и CSV. Фильтры направления, места, ресурса, мышечного акцента, роли в занятии, цели и базовых вариантов. 14 черновых графов с ручной оценкой тренером. Локальный просмотр: `node scripts/reference-preview.mjs`, затем `http://localhost:3060`. Проверка каталога: `npm run catalog:qa`.
