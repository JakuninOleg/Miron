# MIRON provider eval

Это отдельный тест решений модели с синтетическими данными и подставными tools. Он не вызывает приложение, команды тренировок или PostgreSQL. Ответы tools не доказывают реализацию авторизации, идемпотентности, сохранности истории или офлайн-синхронизации MIRON.

Нужны установленный Node.js 24, зависимости проекта и `PLUSVIBE_API_KEY` в локальном `.env.local`. Файл исключён из Git. Не передавать ключ через аргументы команды. Результаты с синтетическими диалогами сохраняются в игнорируемом `.local/ai-eval/`.

По умолчанию запросов к провайдеру нет:

```powershell
node --env-file=.env.local --import=tsx scripts/ai-eval/run.mts
```

Реальный платный прогон включается только явно:

```powershell
node --env-file=.env.local --import=tsx scripts/ai-eval/run.mts --live --models=qwen3.8-omni-flash:cxa --budget-rub=0.5 --label=my-eval
```

Есть `--cases=ID,ID`, `--repeats=1` (до 3), `--deadline-ms=20000`, `--models=...`. Каждый intent ограничен тремя модельными вызовами и четырьмя подставными исполнениями tools. Один общий deadline действует на весь intent. Автоматических транспортных retries нет. UUID/ревизия принадлежат runner, не модели.

Цены читаются из `/v1/pricing` перед прогоном. Локальный guard использует консервативную оценку без скидки кеша, число UTF-8 байтов запроса как оценку верхней границы входа и запрошенный выход 384 токена. Это оценочный guard, а не гарантированный денежный лимит провайдера: поставщик может нормализовать `max_tokens`, а завершение прерванного запроса может тарифицироваться позже. Для строгого внешнего потолка нужен отдельный лимит тестового ключа у провайдера. После обнаруженного `value_clamped:max_tokens` новые кейсы этой модели останавливаются до проверки эффективного ограничения. В тестах 6 октября такой warning был у DeepSeek `cxbc`.

Короткая дополнительная проверка JSON-форматов (6 платных запросов; только синтетические данные):

```powershell
node --env-file=.env.local --import=tsx scripts/ai-eval/probe-json.mts
node --env-file=.env.local --import=tsx scripts/ai-eval/probe-json.mts --live
```

`probe-json` — фиксированная совместимость коротких сообщений, не нагрузочный тест и не проверка гарантированного constrained decoding. Он просит до 128 выходных токенов; DeepSeek нормализовал этот параметр в измеренном прогоне. Фактический bill по отдельному ответу можно сверять по `x-pv-generation-id` через `/v1/generations/{id}`.

`structuralPasses` означает только совпадение tools/аргументов и базовые проверки протокола/текста. Нужен отдельный разбор реплик по `manualChecks`: опасный совет повторить неизвестную запись может пройти автоматическую проверку, если второй tool ещё не вызывался. Подставные действия разрешаются по ожидаемому сценарию и не заменяют независимые бизнес-проверки.

SSE собирается из настоящих дельт, включая tool names и JSON arguments. Текст reasoning не сохраняется; фиксируется только его длина. Подготовленные ответы fixtures не выдаются за ответы модели. Для billing история аккаунта пагинируется по окну времени: параллельное использование аккаунта может попасть в сумму. Баланс может быть округлён, `x-pv-cost-rub` — оценочный заголовок; фактические списания берутся из истории.
