# MIRON beta 0.1

12 октября 2026. Это бета для первых пользовательских проверок. Каталог и изображения техники остаются черновиками. Подписка, питание как отдельный модуль и запуск самостоятельного пользовательского шаблона ещё не подключены.

## Что работает

Яндекс → знакомство один раз → новый дашборд → чат с выбранным напарником → просмотр черновика библиотечного подбора → подтверждение → настоящее занятие → подходы, завершение, XP и приблизительный расход. Во время занятия смена напарника заблокирована. Результаты и черновики принадлежат аккаунту.

ИИ получает ограниченный профиль и фактическое состояние занятия, без email, OAuth-токенов и медицинских документов. История хранится на сервере отдельно по владельцу и персонажу. Повтор одного запроса возвращает сохранённый ответ; неизвестный после обрыва результат не запускает вторую платную генерацию. ИИ только читает факты и готовит предложения. Пересчёт энергии применяется отдельным подтверждением, не меняя XP и записанные подходы.

## Развёртывание

Node 22+, PostgreSQL 18, один экземпляр приложения с 2 ГБ RAM. Сборка выполняется отдельно от runtime. `npm ci`, затем `npm run build:deploy`; команда старта — `npm run start:deploy`, порт `3000`, адрес `0.0.0.0`. Для контейнера используется корневой Dockerfile: в финальном образе только standalone Next, публичные assets, миграции и bundle начального каталога. Секреты не передаются аргументами Docker build и отсутствуют в Git.

Старт применяет версионированные миграции до запуска HTTP. Неуспешная миграция останавливает запуск. `SEED_BETA_CATALOG=true` разрешает идемпотентный импорт исключительно вместе с `APP_RELEASE_CHANNEL=beta`. Статусы упражнений остаются draft; никаких личных данных локальной базы в облако не переносится. После первого успешного импорта можно отключить seed-флаг.

Обязательные runtime-переменные: `DATABASE_URL`, новый случайный `BETTER_AUTH_SECRET` (≥32 символов), `BETTER_AUTH_URL=https://miron-fit.ru`, `AUTH_EMAIL_PASSWORD_ENABLED=false`, `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `ENABLE_AI_ASSISTANT=true`, `PLUSVIBE_API_KEY`, `AI_DAILY_INTENT_LIMIT=200`, `DB_POOL_MAX=5`. OAuth callback в Яндексе: `https://miron-fit.ru/api/auth/callback/yandex`. Нужен ровно этот адрес; локальный callback сохраняется отдельно для разработки.

Голосовой gateway требует отдельного ASR-worker (`VOICE_WORKER_URL` и `VOICE_WORKER_SECRET`); именно worker использует `GROQ_API_KEY` и локальный Whisper. В текущем 2-ГБ web-инстансе worker не установлен, поэтому голос сообщает о недоступности; один ключ Groq распознавание не включает. Без интернета голос и AI-чат отключены, сохранённое занятие и его журнал продолжают работать.

`GET /api/health` возвращает только статус и версию, без конфигурации и секретов. HTTPS обязателен для входа и PWA. Публичные изображения хранятся отдельно от аккаунтов; в публичный S3 нельзя загружать переписку, голос, токены и результаты пользователя.

Для Timeweb PostgreSQL используется `sslmode=verify-full` с официальным CA в `scripts/deploy/timeweb-ca.crt`. Пароль можно передать отдельно в `DATABASE_PASSWORD`; он заменяет пароль URI без отключения проверки сертификата. CA копируется в runtime контейнера.

Публичные иллюстрации перенесены в `miron-beta-public`: 44 объекта, 8 139 875 байт. `MIRON_MEDIA_ORIGIN=https://s3.twcstorage.ru/miron-beta-public` включает выдачу через прежние адреса приложения, поэтому PWA сохраняет тот же публичный кеш. Прокси разрешает только перечисленные папки/форматы, ограничивает размер и время ответа; cookie и заголовки аккаунта не передаются S3. При сбое хранилища используется иллюстрация из сборки. Ключ записи не нужен работающему web-приложению.

Заказанные ресурсы проекта MIRON: PostgreSQL `miron-beta` (4219007), публичный S3 (578237). Согласованный бюджет: web 810 ₽, БД 1 448 ₽ с IPv4 и ежедневной копией, S3 1 ₽ — всего 2 259 ₽/месяц; отдельно трафик S3 и запросы модели. Фактический статус web/домена фиксируется после проверки запуска.

## Ограничения и контроль

Каждый intent: до 2 000 символов входа, 20 секунд, до четырёх model calls и четырёх read tools. Trial — существующие 100 ответов/168 часов от регистрации; глобальный лимит — 200 платных intent в московский день, включая failed/unknown. Расход токенов и подсказка стоимости сохраняются, но последняя не является окончательным счётом провайдера. Локальные сообщения о распознанной боли/острых симптомах не отправляются модели и не расходуют квоту. Эти ограничения не заменяют предметную проверку рекомендаций.

При откате сначала сохраняют базу, затем возвращают прошлую версию приложения. Миграции не откатывают удалением таблиц. При недоступности ИИ выключают `ENABLE_AI_ASSISTANT`; карточки занятия и ручные команды остаются доступны.

## Проверка в зале

1. Войти через Яндекс с телефона, пройти знакомство, открыть чат.
2. Попросить подходящий черновик для зала; просмотреть, подтвердить и запустить.
3. Записать подходы, открыть чат из текущего упражнения, вернуться в занятие.
4. Сохранить занятие офлайн заранее; на несколько минут отключить сеть, записать подход, вернуть сеть и проверить подтверждение.
5. Завершить, проверить результат/XP; сообщить уточнение нагрузки и подтвердить новый приблизительный расход.
6. Повторно войти: знакомство не повторяется, история результата и чата сохранены.
