# MIRON: схема и каталог

Снимок фактического локального PostgreSQL от 6 октября 2026 года. В файлах нет строк аккаунтов, сессий, профилей, паролей и токенов. Схема содержит имена служебных полей авторизации, но не их значения.

- `miron-database.html`: самостоятельный интерактивный справочник. Открывается без сервера и сети; три вкладки для ERD, упражнений и графов навыков. Выбор блока, масштаб и нажатие на таблицу помогают читать связи и поля. CSV должен лежать рядом для ссылки скачивания.
- `miron-database.canvas.tsx`: тот же снимок в интерактивном Canvas для Cursor. Он использует SDK `cursor/canvas` и не входит в сборку Next.js; проверяется отдельно по типам SDK.
- `miron-erd.svg` / `miron-erd.png`: общий обзор всех физических таблиц и FK. SVG поддерживает увеличение без потери качества. Для точных колонок составного ключа и кардинальности используйте интерактивный справочник.
- `exercises.csv`: 300 строк карточек, 55 колонок: короткое и точное имя, алиасы, места, направления, мышцы, ресурсы, метрика, подсказки, ошибки, источники, роли в занятии, цели, поисковые ключи, редакционный приоритет, семантика выполнения, навыковая классификация, требование предварительного навыка, обоснование и активные графы. UTF-8 с BOM, разделитель `;` для Excel.
- `catalog-semantic-qa.csv`: сравнение всех 300 карточек до и после QA с индивидуальными причинами и источниками решений. Подробный отчёт — [catalog-semantic-qa.md](../catalog-semantic-qa.md).
- `db-reference.json`: полный снимок метаданных схемы и неперсонального каталога; источник остальных представлений.

Для просмотра в браузере: `node scripts/reference-preview.mjs`, затем `http://localhost:3060`. Этот сервер слушает только loopback и отдаёт только заранее перечисленные файлы справочника. Сам HTML также открывается напрямую с диска.

В текущей БД: **30 таблиц, 31 FK, 138 семейств и 300 карточек вариантов**. По исходной дисциплине: 220 силовых, 20 мобильности, 30 стретчинга, 30 йоги. Все — `draft`; изображения техники ещё не добавлены. 18 мышечных групп дают 1055 связей с ревизиями. Четыре шаблона предназначены для локального демо.

Фильтры по направлениям пересекаются: 220 силовых, 132 калистеники, 43 стретчинга, 25 мобильности, 31 йоги. По местам: 275 дом, 300 зал, 202 улица/природа, 184 воркаут-площадка. Одна карточка может входить в несколько подборок, поэтому складывать эти числа нельзя. Место не заменяет проверку ресурсов: наличие турника на площадке, крепление и подходящая поверхность указываются отдельно.

Поиск использует имя, алиасы, мышцы, направления, места и поисковые слова. Все слова запроса должны находиться в карточке; работают «молотки», «банка», «попа» и «пресс дома». Точное короткое имя показывается первым, затем основной мышечный акцент запроса, 62 редакционно выбранные базовые карточки и редакционный приоритет; измеренной статистики популярности нет. Вторичные мышцы и стабилизаторы остаются в результатах ниже основного акцента. Есть фильтры роли в занятии, цели и базовых упражнений. Для растяжки и йоги это область фокуса, не обещание роста мышц.

Вкладка «Навыки»: **семь активных черновых графов revision 2, 59 узлов, 59 связей** (18 prerequisite, 41 preparation). Сплошные линии обозначают кандидатов обязательных компонентов, пунктир — подготовительные связи выбранного метода. 14 исторических ревизий V1 сохранены отдельно; физические totals включают обе версии и составляют 21 ревизию, 157 узлов, 148 связей. Узлы закреплены за конкретными ревизиями карточек; оценка ручная. После QA 34 карточки требуют `skill_review`; 35 необоснованных gate сняты. Сложность advanced не создаёт gate. Подготовительная карточка может иметь роль «Практика навыка» при обычном допуске. Графы не задают дозировку, освоение или автоматическое открытие навыков.

Стрелка диаграммы идёт от родительской таблицы к дочерней; каждая стрелка соответствует одному FK, в том числе составному. `profiles` и `ai_trials` ограничены одной строкой на пользователя. Для `media_assets` ссылка на ревизию необязательна. Таблицы `auth_verifications` и `auth_rate_limits` не имеют FK к пользователю.

Копирование шагов и инвентаря в занятие описано текстом и не нарисовано как FK. В текущей схеме нет физических таблиц подписок, платежей, AI-истории и доставки пушей.

Повторить экспорт при работающем локальном PostgreSQL:

```powershell
node --env-file=.env.local node_modules/tsx/dist/cli.mjs scripts/export-db-reference.ts
node docs/reference/render-reference.mjs
node scripts/update-reference-canvas.mjs
node scripts/check-db-reference.mjs
```

Экспорт выполняет `REPEATABLE READ READ ONLY` и разрешает только базу `miron` на loopback:55432. Первые две команды обновляют JSON, CSV и HTML. Скрипт Canvas обновляет встроенный снимок. Проверка Playwright проверяет схему, фильтры, алиасы и экран 390px, затем сохраняет SVG/PNG и снимки интерфейса. Для проверки работающего просмотра можно передать `http://localhost:3060/` аргументом. Дата в интерфейсе позволяет отличить версии.
