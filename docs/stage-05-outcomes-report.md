# Этап 0.5: исходы и защита дневного XP

Реализовано 7 октября 2026 по принятому [ADR 0005](adr/0005-daily-xp-and-workout-outcomes.md).

## Сквозной результат

В UI доступны inline-подтверждения пропуска и досрочного завершения. Сервер определяет completed/partial/aborted, сохраняет прежние подходы и запрещает новые записи после терминального исхода. Пропуск не является нулевым результатом. История показывает исход отдельно; счётчик полных занятий независим от XP.

Main: 50/25, support: 20/10, aborted: 0. Сервер начисляет только разницу до максимальной награды дня; максимум 50, не сумма всех занятий. Полноценная аэробная тренировка может быть main; короткая поддерживающая практика — support. Это категория шаблона, не пол, вес или фактические минуты таймера.

В БД добавлены program_templates.reward_kind, workout_steps.skipped, закреплённые workouts.reward_kind/reward_day и результат reward, daily_xp с PK(user_id,day) и CHECK 0–50. Миграции 0006/0007 применены только к локальному loopback PostgreSQL. UUID упражнений/revisions и V1 snapshots не менялись. Старые XP не удалены и не пересчитаны; консервативный legacy guard защищает день старого начисления и день начала при пересечении полуночи.

Новое занятие получает московскую дату из серверного времени старта. Изменение часов телефона, profile timezone и поздняя синхронизация не перемещают награду в новый день. Транзакция и блокировка владельца сериализуют конкурентные окончания разных занятий. Повтор сохраняет прежний ACK, не создавая XP event. Клиентские day/kind/reward не принимаются строгой схемой API.

Офлайн-клиент сохраняет команды и исход, но на аккаунте не объявляет локально рассчитанный XP. До подтверждения сервера виден статус ожидания. Demo имеет отдельную симуляцию, без серверного аккаунта.

## Проверки

- TypeScript, ESLint и production build прошли.
- Полный Vitest: 91 passed, 12 интеграционных по умолчанию skipped.
- Отдельная проверка домена/PostgreSQL: 18 тестов прошли, включая конкурентные окончания, partial/support top-up, нулевой aborted, сохранение пропущенных результатов, терминальный replay, недопустимый SQL amount=51 и legacy-переход через московскую полночь.
- Браузер: пять прежних product-сценариев прошли, два новых outcomes-сценария прошли. Проверены частичная награда, доплата до 50, reload, отмена без результатов, новый старт, клавиатурный фокус и мобильная ширина.
- Реальный мобильный скриншот итога доплаты просмотрен: `.local/previews/daily-xp-topup.png`.

Cursor CLI (Auto, read-only) проверил три граничных случая политики: достигнутый лимит, меньшая награда второго занятия, доплата 10→50. Он не менял исходники. Backend и UI делались отдельными субагентами; root интегрировал контракты, reducer, журнал, общий XP-модуль и проверки.

## Ограничения и следующий шаг

Защищено начисление, но физическое выполнение вручную отмеченного подхода не доказано. Недельный бонус и XP за достижения не внедрены. Commercial entitlement и срок поздней capability — будущая работа ADR 0004. Персональный календарный timezone наград пока не используется; UI сообщает московское время.

Дальше в 0.5: полные плановые/фактические метрики, неизвестный внешний вес отдельно от нуля и семантика гантелей, версии шаблона/программы/требований и явная версия операции с совместимостью очереди. Парные блоки, разминка и замены остаются следующими инкрементами ADR 0003.
