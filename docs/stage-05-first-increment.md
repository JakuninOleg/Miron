# Этап 0.5: первый инкремент

Дата: 2026-10-07. Реализована первая часть, весь этап ещё не завершён.

Последующий инкремент уже добавил пропуски, partial/aborted и дневной XP: [отчёт](stage-05-outcomes-report.md). Раздел «Дальше» ниже описывает состояние именно первого инкремента.

## Реализовано

Силовой подход подтверждается вручную: повторы и дополнительный вес. Продолжительность подхода и ожидание оборудования не измеряются. Необязательный отдых запускает пользователь.

Временной подход подтверждается отдельной командой `record_timed_set`: фактические целые секунды 1–86400. Для него показаны отдельные таймеры работы и отдыха. Таймер не создаёт результат, не переводит к следующему упражнению и не начисляет XP.

Есть запуск, пауза, продолжение, сброс, остановка и сворачивание. Сворачивание оставляет компактный контрол и не прекращает отсчёт. Переход на другое упражнение или уход со страницы уничтожает локальный таймер; после reload он не восстанавливается.

Отсчёт по deadline догоняет время после задержки вкладки. Завершение показывает галочку и доступный текстовый статус. Звук отключён изначально, включается пользователем; фоновая доставка не гарантируется. Стили используют текущую тему, reduced motion отключает анимацию.

## Данные и совместимость

Миграция `0005_moaning_synch` добавляет nullable `recorded_sets.duration_seconds` и nullable `reps`. CHECK требует либо положительные повторы без секунд, либо положительные секунды без повторов. Для текущего временного контракта дополнительный вес равен нулю; нагруженные временные упражнения потребуют отдельного контракта.

Существующие строки и ID не переписываются. Старые `record_set`, request hash и сохранённые ACK остаются совместимыми, включая старые временные снимки. Их поле `reps` остаётся legacy-данными: миграция не объявляет их подтверждённой длительностью. Новые клиенты отправляют секунды отдельно; интерфейс имеет fallback для старого формата.

`targetDurationSeconds` пока представляет ранее закреплённую дозировку временного шага. Отдельные физические поля всех плановых метрик и версии программ ещё предстоит внедрить. Каталог, UUID revisions и V1 snapshots не менялись; методика остаётся `pending_expert_review`.

Новый payload проходит существующий журнал IndexedDB, проверки владельца, revision, hash и идемпотентный ACK. Сервер отклоняет временную команду для силового шага.

## Проверки

- TypeScript, ESLint, production build: прошли.
- Vitest: 83 теста прошли, 11 интеграционных по умолчанию пропущены.
- Отдельный запуск PostgreSQL integration: 8 тестов прошли, включая ограничения, конкурентные повторы и владельца.
- Playwright на локальной production-сборке: 5 сценариев прошли, включая новые work/rest и ручное подтверждение, мобильный офлайн и существующие сценарии.

## Дальше

1. Skip и completed/partial/aborted, сохранение выполненных подходов при пропуске, без придуманной награды за partial.
2. Полные плановые/фактические метрики, неизвестный внешний вес отдельно от нуля, семантика одной гантели/общего веса.
3. Версии шаблона, программы и требований, закрепление снимков и версия операции с совместимостью прежнего журнала.
4. Парные блоки, разминка, замены и устойчивый контроллер таймеров согласно ADR 0003. В текущем runner пара ещё не реализована.
