## Что покрывают проверки

**База и команды.** Реальные транзакции PostgreSQL проверяют чтение только своего занятия, составные FK владельца, неизменный снимок инвентаря и карточек, конкурентные повторы команды, конфликт одного ID с разными параметрами, ожидаемую revision и одну награду за завершение. Миграции применены; seed можно запускать повторно без перевода draft в published.

**Квота.** Повтор создания профиля не продлевает пробу. Из 130 одновременных резервирований при квоте 100 ровно 100 принимаются. Подтверждение списывает ответ один раз; отмена и истечение освобождают резерв. Это проверка счётчика, а не тарификации Qwen: API ещё выключен, стоимость и качество ответов не измерялись.

**Авторизация.** Реальные письма через локальный Mailpit: регистрация, подтверждение, вход, HttpOnly cookie, одинаковый ответ восстановления для существующей и неизвестной почты, одноразовый reset, отзыв старой сессии и отклонение старого пароля. Заблокированный аккаунт не проходит приватный API. Лимитер разрешает ровно 8 из 20 конкурентных обращений за окно. Unit tests проверяют Origin, ограничение тела, обработку proxy headers и отказ небезопасной production-конфигурации.

Отдельный живой браузерный сценарий прошёл регистрацию → письмо Mailpit → подтверждение → вход → онбординг → проверку `profiles` в PostgreSQL → выход → повторный вход → кабинет → reload. `tests/e2e/auth-live.spec.ts` запускается только с `MIRON_LIVE_AUTH_E2E=1`, проверяет локальные адреса, использует одноразовые данные и удаляет только свой аккаунт. Секреты и ссылки подтверждения не сохраняются в trace.

**Офлайн и повтор запроса.** Состояние и операция атомарно попадают в IndexedDB до HTTP. Проверены повторное открытие хранилища, откат неудачной транзакции, сохранение поздних локальных действий после частичного ACK, одновременный ACK другой вкладки, revision-конфликт и изоляция аккаунтов. Выход/истечение сессии сохраняет неподтверждённый журнал; отправка возможна после свежей авторизации его владельца.

**Браузер.** В собранной PWA: онбординг → запись 9 повторов → reload → загрузка для офлайна → отключение сети → второй подход → reload → запуск через `/` → переходы по ссылкам программы/тренировки без сети → завершение → reload → одна история и 50 XP. Отдельно проверены независимые персонаж/тема, сохранение текста чата и формы восстановления. Состояние «загружено» выставляется после завершения кеширования JS/CSS/fonts/медиа и сохранения данных.

Режим `next dev` проверяет разработку и локальный email-вход. Его горячая перезагрузка требует сети; офлайн-старты проверяются на `next build` + `next start`. Собранное HTTP-демо на `3040` не является публичным сервером авторизации.

## Ограничения и следующий допуск

- Реальный Qwen, внешняя почта и Яндекс/VK round trip ещё не прошли сквозную проверку. Подготовленные реплики не выдаются за ответы модели.
- 300 вариантов остаются редакционными draft. Четыре шаблона служат локальной демонстрации. Опубликованные персональные программы, иллюстрации техники и редакторская публикация ещё впереди.
- Поля расписания сохранены; Web Push, VAPID, очередь уведомлений и фоновые задачи доставки ещё не реализованы.
- Подписка, платежи в рублях и коммерческие подключения ещё не реализованы.
- Локальный PostgreSQL запускается с отдельной административной ролью. Перед размещением нужны роли приложения/миграций, контроль доступа к secret/backup, восстановление резервной копии и выбор инфраструктуры в РФ.
- Ограниченный pool, индексы, транзакции и идемпотентность заложены. Нагрузочный тест тысяч одновременных пользователей, мониторинг, аварийное восстановление и проверка многосерверного размещения ещё не выполнены.
- Телефон, установка PWA на iOS/Android, системные пуши и Speech Recognition на реальном устройстве требуют отдельного HTTPS-стенда и проверки.

Полный `npm audit` показывает **5 high записей в dev-цепочке** `braces → micromatch → fast-glob → eslint-config-next`. Исходная [advisory braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) относится к глубоко вложенным glob-шаблонам; текущая доступная версия 3.0.3 входит в диапазон. Эта цепочка отсутствует в production-зависимостях. Сохранён поддерживаемый Next; `audit fix --force` с откатом на старый Next не применялся. Обновить dev-цепочку после исправления upstream; до этого не обрабатывать недоверенные шаблоны этими инструментами.
