# Питание MIRON: реализуемая вертикаль

18 октября 2026. Макеты: [телефон](visuals/nutrition-2026-10-18-v1/01-mobile.png), [десктоп](visuals/nutrition-2026-10-18-v1/02-desktop.png). Числа на макетах иллюстративны; приложение считает по исходным продуктам.

`/nutrition`: предпочтения, общие идеи меню, ручное добавление/замена/удаление блюд, отдельный журнал съеденного, исправление порции, библиотека своих блюд. Запланированное не становится съеденным без подтверждения. Съеденное хранит снимок блюда, количества, режима и расчёта; последующие изменения рецепта, меню или режима не переписывают прошлое. XP за еду и ограничение калорий отсутствуют. Расход от тренировки не создаёт разрешение на еду или обязательство её «отрабатывать».

«Без заморочек» — приблизительные порции; «Дотошный» — граммы; можно скрыть числа. Усреднённая пищевая ценность не является измерением усвоения или личной нормы. Неполный журнал даёт только частичную сумму. Неизвестная пищевая ценность собственного блюда хранится как null и отдельно отмечается, а не считается нулём.

## Источник

Выборка 16 продуктов из Public Health England, **McCance and Widdowson's Composition of Foods Integrated Dataset 2021**, таблица 1.3 Proximates, колонки J/K/L/M на 100 г. [Страница и лицензия OGL](https://www.gov.uk/government/publications/composition-of-foods-integrated-dataset-cofid), [исходный XLSX](https://assets.publishing.service.gov.uk/media/60538b91e90e07527df82ae4/McCance_Widdowsons_Composition_of_Foods_Integrated_Dataset_2021..xlsx). В `src/shared/data/cofid-foods.json` сохранены оригинальные food code/name, перевод, значения и признаки ингредиентов. Tr округлён до нуля на уровне состава; неизвестные N не импортировались. Коэффициенты готовой/сырой массы не смешиваются: базовые рецепты используют готовые рис/пасту/чечевицу/мясо, овсяную кашу на воде. Пример порции — редакционное допущение, которое пользователь может изменить. Изображения сгенерированы, показывают сервировку, не доказывают состав.

Первые девять блюд — общие варианты, не полный сбалансированный персональный рацион и не лечебное меню. Вариация по дню, предпочтениям, исключённым продуктам и выбору без мяса/рыбы; приготовленная овсянка исключается вместе с овсом. Собственные блюда автоматически не предлагаются при подборе: их состав не проверен.

## Ограничения и согласия

Перед общими идеями меню интерфейс спрашивает об аллергиях/лечебных ограничениях. Ответ существует только в памяти открытого экрана, в БД/ИИ не отправляется. При ответе «Есть или не уверен» автоматические идеи блокируются; остаётся ручной выбор по проверенному пользователем составу. Автоматическая персонализация по медицинским данным требует отдельного опубликованного согласия, полных ингредиентов/следов и предметных проверок; текущий модуль этого не имитирует. [NHS: проверять маркировку и риск контакта с аллергенами](https://www.cuh.nhs.uk/patient-information/milk-allergy/). Юридические проекты с пустыми реквизитами не превращены в действующие согласия.

На этом этапе питание сохраняется онлайн; отдельной офлайн-очереди еды пока нет. Тренировочный журнал остаётся самостоятельным. Новый API private/no-store, с owner fence, bounded input, ожидаемой ревизией, блокировкой пользователя и идемпотентной квитанцией в одной транзакции. После ACK UI перечитывает актуальную запись, не восстанавливает устаревшее меню из локального запроса.
